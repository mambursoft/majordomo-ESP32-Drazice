# AGENTS.md — правила для розробників та AI-агентів

Цей файл обов'язковий до прочитання перед будь-якими змінами.

## Непорушні правила безпеки продакшену

1. **Жодних секретів у Git.** Wi-Fi паролі, BLE MAC, PIN, паролі HTTP/OTA — лише
   в `firmware/secrets.yaml` (у `.gitignore`) або приватній конфігурації
   модуля. Приклади — у `*.example.*`.
2. **Без MQTT і без обов'язкового Home Assistant.** Транспорт — PHP cURL до HTTP
   REST ESPHome.
3. **PHP 7.3.** Жодних typed properties, union types, `match`, nullsafe `?->`,
   arrow-функцій у стилі 7.4+, `str_contains`/`str_starts_with`. Перевіряти
   `php -l` і тести саме під 7.3-сумісним синтаксисом. Цільова БД — MariaDB 10.3.
4. **Жодних живих записів за замовчуванням.** Модуль стартує `automationEnabled=false`,
   `dryRun=true`. Реальне керування бойлером — тільки після явного погодження.
5. **Nginx не чіпати без потреби.** Якщо зміни погоджені: backup →
   `sudo nginx -t` → лише при успіху `sudo systemctl reload nginx`. Зберегти
   `$without_megad`, LAN-винятки, маршрути MegaD і TV.
6. **Бекап перед редагуванням** кожного файлу на продакшені; dump релевантних
   таблиць перед міграцією. Пароль БД — лише з `~/.my.cnf`.
7. **ESP32 не публікувати** через публічний роутер (80/443). Доступ — лише з
   довірених вузлів локальної мережі.

## Межі апаратного керування

- Прошивка **не комутує** ТЕН. Жодних GPIO-реле на силових колах.
- BLE — не safety-rated канал. Втрата зв'язку не гасить нагрів.
- STOP недоступний як команда (підтверджено кодом upstream). ANTIFROST — режим
  захисту від замерзання, а не OFF. Зниження target не гарантує зупинки нагріву.

## CI (без контакту з реальним бойлером)

- `php -l` на всіх PHP-файлах (7.3-сумісність).
- Юніт-тести: planner (fixtures), policy engine, transport (URL-кодування,
  SSRF-захист), tariff/offset/DST.
- Перевірка `firmware-api-manifest.json` проти схеми.
- `esphome config` (валідація YAML) — опційно, якщо esphome доступний.
- Сканування на секрети та перевірка ліцензій.

## Відтворюваність

- Pinned версії: ESPHome, framework, upstream commit — у
  `requirements-build.lock`, `firmware/firmware-api-manifest.json`,
  `THIRD_PARTY_NOTICES.md`.
- Не видавати test skeleton за пройдені тести. У `docs/test-report.md` кожен
  пункт — PASS / FAIL / NOT RUN з методом, версією, датою.

## Чого НЕ робити

- Не вигадувати BLE-протокол, адреси регістрів, назви властивостей прогнозу чи
  адреси Flash. Фіксувати фактичні значення або позначати як непідтверджені.
- Не підмінювати відсутні дані нулями (`0 °C`, `0 kWh`). Відсутнє = `unavailable`.
- Не змішувати синтаксис esptool 4.x і 5.x у командах.
