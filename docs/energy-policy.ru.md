# Энергополитика и планировщик

Планировщик **детерминированный и объяснимый**: одинаковые входные данные →
одинаковое решение, всегда поясняет «почему греет / почему нет». Без ИИ в контуре.

## Приоритеты (от высшего)

1. **Аппаратные защиты** — не заменяем.
2. **Непригодные данные** (ESP недоступен, неизвестен Heat, нет температуры) → `hold`.
3. **Cooldown / лимит длительного нагрева** — не обходится.
4. **Батарея**: питание от батарей → новые пуски запрещены.
5. Гигиена/комфорт (конфликты показываем человеку).
6. **Ручной boost** с TTL — не обходит пункты 1–4.
7. **Комфортный минимум** — ниже него греем.
8. **Солнечный избыток** по SOC / **ночной тариф**.

## Солнечный избыток по SOC батареи

Если **днём** заряд батареи (`deye_battery.soc`, можно переназначить) достигает
порога (обычно **100%**) — есть избыток генерации, тратим его на нагрев воды,
пока SOC не упадёт до нижнего порога (обычно **98%**). Гистерезис избегает частых
переключений. Работает **даже без** модуля прогноза — напрямую по SOC. Ночью /
от батареи / в cooldown избыток нагрев **не** включает.

## Ночной тариф

Считается по часам счётчика (вкладка «Тариф»): окно `23:00–07:00`, с учётом DST
(Europe/Kyiv), погрешности часов счётчика и защитных отступов. Детали — в
`lib/Tariff.php` и `tests/Unit/TariffTest.php`.

## Температуры

`comfort_min`, `night_target`, `solar_target`, `boost_target`, `absolute_max` —
**отправные точки**, не универсально безопасные. Согласуйте с инструкцией бойлера.
Диапазон — 40–80 °C (аппаратное ограничение).

## Безопасно по умолчанию

Старт: `AUTOMATION_ENABLED=0`, `DRY_RUN=1`. Решения считаются и показываются, но
бойлеру не отправляются, пока вы явно не включите автоматику и не выключите dry-run.
