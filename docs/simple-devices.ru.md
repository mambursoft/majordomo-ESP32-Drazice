# Бойлер как «Простое устройство» MajorDoMo + сканирование/выбор MAC

Документ объясняет две вещи, управляемые прямо из MajorDoMo:

1. **Сканирование BLE-бойлеров и выбор MAC** — во вкладке «Устройства» модуля.
2. **Интеграция бойлера в штатный модуль «Простые устройства»** (devices) —
   чтобы бойлер был обычным термостатом в стандартном интерфейсе, сценах,
   комнатах и приложении, а не только в собственной панели модуля.

Все функции прошивки видны и управляемы из MajorDoMo: температуры, нагрев (Heat),
HDO, энергия; запрос режима и целевой температуры (через локальную защиту ESP32);
состояние guard, cooldown, lease, причина решения; диагностика ESP32; кнопки
Release/Reconnect BLE, обновление lease, сопряжение по PIN; солнечный избыток по
SOC, ночной тариф, boost, присутствие.

---

## 1. Сканирование BLE-бойлеров и выбор MAC (вкладка «Устройства»)

ESP32 нужен Bluetooth-адрес (MAC) бойлера. Угадывать не нужно — модуль покажет
найденные устройства и даст выбрать.

### Шаг 1. Включите BLE-сканер на ESP32

- **Проще всего:** прошейте диагностическую прошивку `firmware/boiler-scan.yaml`
  (только сеть + сканер). См. `flashing-windows11.ru.md`.
- Или добавьте пакет `packages/ble_scan.yaml` в основную прошивку. Внимание:
  одновременное активное сканирование + рабочий BLE-клиент нагружают стек — для
  поиска MAC лучше отдельная прошивка.

Убедитесь, что **фирменное приложение Drazice отключено** от бойлера.

### Шаг 2. Выберите бойлер в MajorDoMo

1. Модуль «Drazice SMART Boiler» → вкладка **«Устройства»**.
2. Прокрутите до **«Сканировать бойлеры по Bluetooth»**.
3. Появится таблица найденных BLE-устройств: MAC, имя, RSSI. Похожие на бойлер —
   вверху, зелёные.
4. Нажмите **«Выбрать»** напротив вашего бойлера. MAC сохранится в модуле.
5. Кнопка **«Очистить список и сканировать снова»** сбрасывает список на ESP32.

### Шаг 3. Примените MAC в прошивке

Впишите MAC в `firmware/secrets.yaml` (`boiler_ble_mac`) и прошейте основную
`boiler-weact.yaml`. ESP32 читает MAC из secrets при загрузке (не меняется по
HTTP на лету ради безопасности).

## 2. Интеграция «Простые устройства» (вкладка «Простые устройства»)

Модуль может создать и синхронизировать бойлер как штатные устройства
(`SThermostats`, `STempHumSensors`, `SPowerSensors` и т.п.).

| Ключ | Тип (по умолч.) | Назначение |
|---|---|---|
| `thermostat`  | `SThermostats`    | термостат: текущая/целевая t°, режим, реле = Heat |
| `temp_lower`  | `STempHumSensors` | нижний датчик температуры |
| `energy`      | `SPowerSensors`   | накопленная энергия |
| `battery_soc` | `SSensors`        | заряд батареи (SOC) |
| `hdo`         | `SControllers`    | состояние тарифного входа HDO |

> Типы простых устройств в вашем MajorDoMo могут иметь другие ключи. Сверьте со
> списком в «Устройства → Добавить» и при необходимости отредактируйте карту
> (JSON). Модуль не выдумывает типы — создаёт ровно то, что вы указали.

### Важно о безопасности (relay_readonly)

Термостат создаётся в режиме **`relay_readonly`**: штатная логика термостата
**не управляет** ТЭНом сама — только **показывает** состояние. Все реальные
команды идут через локальную защиту ESP32 (cooldown / lease / readback). Смена
целевой температуры в интерфейсе устройств перехватывается и отправляется через
guarded REST.

### Как включить

1. Вкладка **«Простые устройства»** → отметьте **«Включить интеграцию»**.
2. (Необязательно) отредактируйте **«Карту устройств (JSON)»** (пусто = типовая).
3. Сохраните, затем **«Создать простые устройства»** (идемпотентно).
4. Откройте штатный модуль **«Устройства»** — бойлер там. Дальше синхронизация
   автоматическая в цикле.

### Что синхронизируется

- `value` термостата ← верхний датчик (текущая t°);
- `currentTargetValue` ← запланированная/запрашиваемая цель (показ);
- `relay_status` ← Heat (только показ, relay_readonly);
- сенсоры `.value` / `.status` ← нижний датчик, энергия, SOC, HDO.

Смена `currentTargetValue` в UI → guarded REST → бойлер (с readback).

## 3. Единый объект бойлер+ESP (`EspBoiler`)

Модуль ведёт **один объект** `EspBoiler` (имя настраивается, `BOILER_OBJECT`),
представляющий **бойлер и его ESP32 как одно целое**. В него пишется всё:
телеметрия бойлера (`tempUpper`, `tempLower`, `heating`, `hdo`, `reportedMode`,
`energyTotalKwh`, `boilerVersion`…), диагностика ESP (`espUptime`, `espRssi`,
`guardState`, `cooldownRemaining`, `leaseRemaining`…), планировщик
(`powerSource`, `batterySoc`, `plannedTarget`, `decisionHuman`…) и присутствие
(`presentPeople`, `presenceSessionJson`, `presenceEvent`, `presenceEventJson`).

Каждое свойство имеет **описание** (DESCRIPTION). Управляющие свойства помечены
«⚙ КЕРУВАННЯ» и к ним привязан метод — изменение применяется к бойлеру через
guarded REST:

| Свойство | Действие |
|---|---|
| `requestedTarget`   | Целевая температура, °C (40..80) |
| `requestedMode`     | Режим: ANTIFREEZE/SMART/PROG/MANUAL |
| `boost`             | 1 — разовый boost; 0 — отмена |
| `automationEnabled` | 1/0 — автоматика |
| `allowBatteryHeat`  | 1 — разрешить нагрев от батарей |

Остальные свойства — только чтение (модуль перезапишет их из ESP).

## 4. Нагрев от батарей (безопасно)

По умолчанию заблокирован. Включите `allowBatteryHeat` или boost с разрешением
на батарею. Безопасность бойлера (лимит длительного нагрева, cooldown)
сохраняется — она выше разрешения на батарею.

## 5. Сканер смартфонов, биндинг и события присутствия

Определение — по **Bluetooth** (сканер ESP, источник `ble`) и **Wi-Fi**
(`EspBoiler.wifiObservationsJson` из arp роутера, источник `wifi`). Биндинг — в
«Список MAC → имя (JSON)»: `{"aa:bb:..":"Назар"}`.

### События, если ребёнок долго в туалете

| Событие | Когда |
|---|---|
| `entered`  | человека впервые увидели (начало сессии) |
| `long`     | дольше «порога долго» (`PRESENCE_NOTIFY_AFTER_S`) |
| `too_long` | дольше «порога очень долго» (`PRESENCE_TOO_LONG_AFTER_S`) |
| `left`     | исчез из эфира (конец сессии) |

Каждое событие вызывает обработчик (`PRESENCE_HANDLER`) с `person/duration_s/
event`, пишется в объект (`presenceEvent`/`presenceEventJson`) и в таблицу
`drazice_presence`.
